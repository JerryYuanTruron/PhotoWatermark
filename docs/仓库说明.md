# 仓库说明

## 1. 名称与用途

| 项 | 内容 |
|---|---|
| 仓库名称 | `PhotoWatermark` |
| 中文名称 | 批量照片时间水印处理程序 |
| 用途 | 按客户照片规范（BMW EEPH PH_C）批量处理 DUT 照片：统一 4:3 比例与像素规格、叠加 EXIF 拍摄时间水印、合规命名并批量导出，同时给出逐张状态与失败清单 |
| 使用者 | 生产线操作人员（GUI）、维护开发者（源码/构建）、质量人员（报告与验收） |
| 交付形态 | 免安装单文件 exe + 源码 + 文档；exe 不入库，由 `build.py` 从标签提交构建 |

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.10+（开发验证 3.12） | 标准库为主 |
| GUI | tkinter / ttk | Windows 自带，无第三方 UI 依赖 |
| 图像 | Pillow | 解码、裁切、缩放、绘制、EXIF/ICC 读写 |
| 打包 | PyInstaller 6.x | onefile + windowed |
| 测试 | 自研轻量断言 + 子进程验收 | 无 pytest 依赖，`tests/run_all.py` 一键执行 |
| 版本管理 | Git + annotated tag | `VERSION` 与 `src/__init__.py` 双写版本 |

## 3. 初始化方式

### 3.1 克隆已有仓库

```bash
git clone <仓库地址> PhotoWatermark
cd PhotoWatermark
py -3 -m venv .venv
.venv\Scripts\activate
py -3 -m pip install -r requirements.txt
py -3 main.py            # 源码运行
```

### 3.2 从零建立同类仓库（本仓库最初的初始化方式）

```bash
mkdir PhotoWatermark && cd PhotoWatermark
git init
git branch -M master
# 建立目录：src/ tests/ docs/ dist/（dist 忽略）
# 写入 VERSION、requirements.txt、.gitignore、README.md、CHANGELOG.md
git add .
git commit -m "chore: 初始化项目骨架与 v1.0.0 版本基线"
git tag -a v1.0.0 -m "v1.0.0 首个可交付版本"
```

> 本仓库的实际首个提交为 `ce89cb0 chore: 初始化项目骨架与 v1.0.0 版本基线`（2026-11-07）。

## 5. 配置文件说明

| 文件 | 作用 | 约定 |
|---|---|---|
| `requirements.txt` | 运行依赖（Pillow） | 新增依赖必须同步此文件与 `docs/技术文档.md` 依赖表 |
| `.gitignore` | 忽略 `dist/*.exe`、`build/`、`__pycache__`、`_test_*`、`rules/last_used.json` 等 | 交付 exe 与构建档案不入库，避免二进制膨胀 |
| `.gitattributes` | 统一换行（`*.py` LF、`*.bat` CRLF）、标记二进制 | 避免跨平台整文件 diff |
| `LICENSE` | 专有/保密声明 | 如需开源须整体替换，并在 CHANGELOG 记录 |
| `VERSION` | 版本号唯一来源之一 | 发版时与 `src/__init__.py::__version__` 同步 |
| `PhotoWatermark.spec` | PyInstaller 打包配置 | 由 `build.py` 生成/覆盖，可重建 |
| `README.md` / `docs/技术文档.md` | 使用说明 / 维护文档 | 功能或行为变更须同步更新 |

## 6. 提交与发布规范

- 分支：`master`，线性历史，不强制多分支。
- 提交信息：`type(scope): 摘要`，`type ∈ {feat, fix, test, docs, chore, build, perf}`；
  正文列“改动 / 验证”，一次提交只做一件事。
- 版本：语义化 `MAJOR.MINOR.PATCH`；改版本需同时更新 `VERSION`、`src/__init__.py`、`CHANGELOG.md`。
- 标签：每次发布打 annotated tag `vX.Y.Z`，标签正文写明验证计数与关键边界。
- 发布顺序：全量测试 → 提交 → 从干净 HEAD `build.py` → `validate_frozen.py` → 打标签。
- 二进制：exe 不提交，由标签提交重建；`BUILD_INFO.txt` 记录 HEAD 与源码/exe sha256。
