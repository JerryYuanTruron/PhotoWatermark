## 1. 项目说明

### 1.1 用途

面向生产线操作人员的 Windows 桌面程序：**一次批量导入照片 → 自动完成尺寸/比例处理 → 叠加 EXIF 拍摄时间水印 → 批量导出 → 逐张状态与失败清单**，用于 BMW EEPH PH_C 项目的照片存档与客户交付。

### 1.2 依据

| 来源 | 内容 |
|---|---|
| `How to photo documentation_V2.doc`（V2.0，2026/05/25） | 第 9 节步骤 3.1–3.11：XnConvert 批量加水印流程（文字、EXIF 拍摄日期、右下、微软雅黑、阴影、输出改名、状态显示） |
| `How to_ photo documentation-v1-20260515_075710.pdf`（V1，CONFIDENTIAL） | p.3：≥2100 万像素、4:3、每张须有可见时间戳、命名 `<ECU>_<serial>_<seq>` |

### 1.3 交付形态

| 形态 | 说明 |
|---|---|
| 免安装 exe | `dist/PhotoWatermark.exe`（PyInstaller onefile + windowed，约 29.4 MB），目标机无需 Python |
| 源码运行 | `run.bat` 或 `python main.py`（需 Python 3.10+ 与 Pillow、tkinter） |
| 构建档案 | `dist/BUILD_INFO.txt`：版本、构建时间、解释器、PyInstaller 版本、git HEAD/脏标记、逐源码 sha256、exe sha256 |

## 2. 功能清单

1. **批量导入**：多文件/文件夹（可含子文件夹）、自动去重；支持 JPG/PNG/BMP/TIF/WEBP。
2. **导入期检查**（不阻断导入）：
   - EXIF 检查：缺拍摄日期 → 弹窗提示「请提供保留完整 EXIF 的原始照片」，状态表标记，处理时判失败；
   - 比例/方向检查：非 4:3 或竖版 → 非模态窗口列出文件、异常类型、目标要求与建议（横版自动裁边、竖版需人工确认方向）。
3. **处理链**：解码 → EXIF 方向校正 → 读取拍摄日期 → 居中裁边到 4:3 → 时间水印 → 临时文件写出 → 回读校验 → 原子替换。
4. **时间水印（系统固定）**：内容仅 `yyyy/mm/dd hh:mm:ss`，右下，微软雅黑 210 px，按背景自动取深/浅墨色 + 反色阴影；界面不可见、规则文件不可改。
5. **合规口径（只读）**：≥21 MP 校验、`crop43`、`{ecu}_{serial}_{seq}`（三位序号 001–999）。
6. **逐张状态**：成功/警告/失败/跳过 + 失败阶段与原因；失败照片清理残留成品。
7. **报告**：`失败清单.csv`（UTF-8 BOM，Excel 直开）、`失败清单.txt`、`处理报告_*.txt/.json`（含规则快照与逐张结果）。

## 4. 架构与模块职责

### 4.1 分层

```
tkinter UI (ui.py)
   │  收集 RuleConfig、调度后台线程、展示 ProcessResult
   ▼
engine.process_one()  ← 单张纯函数式处理，不依赖 GUI
   │  config.RuleConfig（规则）  reporter.summarize/export_reports（汇总）
   ▼
Pillow（解码/缩放/裁切/绘制/编码）
```

- **无全局状态**：单张处理所需信息全部由 `RuleConfig` 传入，便于测试与并发。
- **UI 与引擎解耦**：`engine` 不 import `ui`；`ui` 只调用公开函数。
- **失败即数据**：`process_one` 永不抛出未捕获异常，任何问题都转成 `ProcessResult(status, stage, reason)`。

### 4.2 关键数据结构

`ProcessResult`（`src/engine.py`）字段：

| 字段 | 含义 |
|---|---|
| `status` | 成功 / 警告 / 失败 / 跳过 |
| `stage` | 失败阶段：导入 / 时间源 / 尺寸调整 / 水印渲染 / 命名 / 导出 / 输出校验 |
| `reason` | 失败或需人工关注的具体原因 |
| `warnings` | 非阻断说明（字体回退、自动缩字号、裁边像素数、对比度偏低等） |
| `watermark_text` / `watermark_color` / `watermark_contrast` | 实际水印文本、自动取色结果、字形区域实测亮度差 |
| `output_path` / `attempted_output` | 成品路径 / 本次尝试写出的路径（供审计反向核对残留） |
| `output_megapixels` / `verified` | 成品像素数 / 是否通过回读校验 |

## 5. 处理流程（单张）

| 阶段 | 关键动作 | 失败判定示例 |
|---|---|---|
| 0 命名 | 计算 `起始序号 + 张序 - 1`，超过 999 直接失败 | 序号越界（不产出文件） |
| 1 导入 | 存在性/扩展名/解码/解压炸弹保护 | 损坏、非图片、超大像素 |
| 2 时间源 | 读 `DateTimeOriginal > DateTimeDigitized > DateTime`；缺 EXIF 按策略（默认失败） | 缺 EXIF、字段不可解析 |
| 3 尺寸 | `crop43` 居中裁边（横版）；`contain/cover/stretch/none` 可选 | 内存/尺寸异常 |
| 4 水印 | 210 px 微软雅黑；按水印区域背景中位亮度取深/浅墨；反色阴影；渲染后像素级自检 | 画布过小、图层为空、变化像素不足 |
| 5 导出 | 写临时文件 → 回读校验 → `os.replace` 原子替换；保留 EXIF/ICC | 磁盘/权限/编码失败 |
| 6 校验 | 可解码、目标尺寸、DPI、文件大小、格式、像素数 ≥21 MP | 任一不符即失败并删除残留 |

失败统一走 `abort()`：清理临时文件、清空 `output_path`、保留 `attempted_output`，保证「判失败不产出」。

## 6. 配置模型

### 6.1 可配置（高级设置，界面可见）

输出规格（目标宽高、DPI、格式、JPEG 质量、背景色）、输出与命名（同名策略、保留元数据、报告版副本）、输出校验（回读校验、最小字节、源像素上限）。

### 6.2 系统固定（不可配置）

| 组 | 字段 | 值 |
|---|---|---|
| 时间水印（22 项） | 内容/格式/位置/字体/字号/颜色/阴影/时间来源/缺 EXIF 策略 | 仅时间、`%Y/%m/%d %H:%M:%S`、右下、微软雅黑 210 px、自动取色、阴影启用、EXIF、失败 |
| 合规口径（3 项） | `resize_mode` / `min_output_megapixels` / `filename_template` | `crop43` / `21` / `{ecu}_{serial}_{seq}` |

落地方式：
- 界面：水印字段完全不出现；合规三项以只读标签展示；
- `_collect_config()` 末尾调用 `apply_fixed_watermark().apply_compliance_lock()` 强制回写；
- 规则文件载入只回填可编辑字段；
- 引擎入口再次 `apply_fixed_watermark()`（水印）；合规项在引擎层保留可传参，供自动化测试与内部批处理使用。

### 6.3 持久化

`rules/last_used.json`（exe 同级，可用环境变量 `PW_RULES_DIR` 重定向）。仅保存可编辑字段与三项必填（ECU、样品编号、输出目录），下次启动自动带入。

## 8. 构建

### 8.1 一键构建

```bat
build_exe.bat
```

或：

```bat
py -3 build.py
```

`build.py` 行为：
1. 校验工作区（存在未提交源码改动时拒绝产出可交付 exe）；
2. 调用 PyInstaller（onefile/windowed，独立 `--workpath`，避免批量删除中间目录）；
3. 计算逐源码 sha256，写 `dist/BUILD_INFO.txt`（含 git HEAD、`git_dirty`、exe sha256）；
4. 清理 `dist/rules`（启动配置不随包分发），并在 `dist/输出照片` 非空时打印分发警告。

### 8.2 产物

```
dist/PhotoWatermark.exe      # 单文件，免安装
dist/BUILD_INFO.txt          # 构建档案（可回溯）
```

### 8.3 构建后验收

```bat
py -3 tests\validate_frozen.py
```

覆盖：版本元断言、BUILD_INFO 与源码/exe 哈希一致、产物内自检（`--selftest`）、双击启动窗口实测、关闭后无残留、交付目录不含 `rules/`。

### 9.2 源码

```bat

:: 或

```

### 9.3 无界面模式（自动化/验收）

```bat
PhotoWatermark.exe --version  <输出JSON路径>
PhotoWatermark.exe --selftest <工作目录>
```

- `--version`：写出程序名、版本、源码/产物标识，便于外部核对；

## 11. 版本管理与发布

- 版本号：`VERSION` + `src/__init__.py::__version__` 双写，发布时同步 `CHANGELOG.md`。
- 分支：`master` 线性提交；提交信息采用 `type(scope): 摘要`（`feat`/`fix`/`test`/`docs`/`chore`/`build`），正文列改动与验证。

## 12. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 启动即报「缺少 EXIF 信息」 | 原图经聊天工具/截图传输被剥离 EXIF | 提供保留完整 EXIF 的原始照片 |
| 整批提示比例不符 | 源图为 1.43:1（如 8768×6144） | 默认会自动裁到 4:3；若裁切影响内容，需重拍/换图 |
| 文件名序号异常（4 位） | 起始序号+张数超过 999 | 拆批；界面会在开始前提示 |
| 水印颜色与预期不同 | 按背景自动取深/浅墨 | 属预期行为，报告中可查实际颜色与对比度 |
| exe 被杀软拦截 | 未签名 + onefile 自解压 | 加白名单；或改用 onedir 构建 |
| 报告写不出 | 输出目录只读/磁盘满 | 改输出目录，检查权限与空间 |

## 13. 已知限制

1. 拍摄顺序（标签闭环、六面视图、连接器、异常细节）未做程序化校验，需人工按规范核对。
2. 输出回读校验不覆盖水印可见性、时间戳语义、命名规范、画质。
3. 竖版/正方形不做破坏性裁切，保持原样并降级为警告。
4. 单批序号上限 999；跨批连续性需人工指定起始序号。
5. HEIC/HEIF 不支持；TIF/BMP/WEBP 统一转 JPEG。
6. 未做代码签名；onefile 冷启动需解压，约数秒。
