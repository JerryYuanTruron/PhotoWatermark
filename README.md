# 批量照片时间水印处理程序 v1.2.1

面向操作人员的 Windows 桌面程序：填 3 项必填信息 → 一次批量导入 → 一键处理，
自动完成 **尺寸与像素规格调整 → 系统固定时间水印 → 批量导出 → 逐张状态与失败清单**。

- **免安装版**：`dist/PhotoWatermark.exe`（单文件，目标机器无需 Python）
- **源码运行**：双击 `run.bat`（需 Python 3.10+ 与 `Pillow`，执行 `pip install -r requirements.txt`）
- **流程依据**：`How to photo documentation_V2.doc`（V2.0，2026/05/25）第 9 节步骤 **3.1–3.11**
- **客户规范**：`How to_ photo documentation-v1-20260515_075710.pdf`（V1，CONFIDENTIAL，2026/05/15）第 1 节
- **v1.2.1 变更**：同名文件**默认不覆盖**（自动加序号另存）；开始处理前统计同名文件并明确提示后果
- **v1.2.0 变更**：必填项前置集中；时间水印改为**系统统一生成、固化不可修改**（仅 `yyyy/mm/dd hh:mm:ss`）
- **v1.1.2 变更**：导入时校验 4:3 横版比例与方向，逐张列出异常与处理建议。详见 `CHANGELOG.md`
- **v1.1.1 变更**：缺少 EXIF 时弹出简洁提示窗口；触发判断只依据照片 EXIF。详见 `CHANGELOG.md`
- **v1.1.0 变更**：「≥2100 万像素强制校验 + 合规命名 + 严格 EXIF 口径」。详见 `真实照片核查报告_20261107.md`

## 1. 三步完成一次批量处理（必填项已前置）

| 步骤 | 操作 | 说明 |
|---|---|---|
| ① 填必填信息 | 顶部「第 1 步 · 必填信息」：**★ ECU 名称**、**★ 样品序列号**、**★ 输出目录** | 集中前置、红色 ★ 标识；未填满时「② 开始批量处理」禁用，空值输入框浅红底提示。填过的值下次启动自动带入，无需重复输入；输出目录默认程序目录 `输出照片/` |
| ② 导入照片 | 「① 导入照片」/「① 导入文件夹」 | 可多选、可勾选「包含子文件夹」、自动去重；支持 JPG/PNG/BMP/TIF/WEBP；导入时校验 4:3 横版比例与方向 |
| ③ 开始处理 | 「② 开始批量处理」 | 后台处理，进度条 + 逐张状态实时刷新；完成后自动写出失败清单与处理报告 |

**时间水印由系统统一生成、固化不可修改**：内容只有 `yyyy/mm/dd hh:mm:ss`（例 `2026/11/05 16:08:32`），
不附加任何文字、标识或可变信息（文件名、序号、ECU 等都不进入水印）。界面**不提供任何水印选项**
——没有启用开关、没有时间格式、没有内容模板、没有字体/位置/字号/颜色/阴影设置；
规则文件与脚本同样无法改写（详见第 3.2 节）。时间取自照片 EXIF 拍摄日期，
同一张照片重复处理得到完全相同的水印文本与外观。

导入后程序做两项固定检查，均**不阻断导入**：

- **EXIF 检查**：仅依据照片 EXIF。缺少 EXIF 信息时弹出简洁提示窗口，并在状态表标记、处理后列入失败清单；含 EXIF 的照片不弹窗，按原流程正常处理。
- **比例 / 方向检查**：仅依据文件内实际像素宽高（目标为**符合 4:3 的横版照片**，宽高比容差 1%）。发现不合格照片时弹出一个**非模态、可滚动**的提示窗口，列出全部受影响文件、异常类型、目标要求与处理建议；合格照片及被标记的照片都照常保留在导入列表，状态表把异常行标为「比例异常」。

| 情形 | 提示中的建议 |
|---|---|
| 竖版且旋转 90° 后正好是 4:3 横版，EXIF 方向标记为 6 / 8 | 依据方向标记给出**顺时针 / 逆时针**旋转 90°；程序处理时会自动按标记校正，无需手工旋转 |
| 竖版且旋转后是 4:3 横版，但无可靠方向依据（方向标记为 0/1/2/3/4/5/7 或缺失） | 提示**人工确认旋转方向，程序不指定方向** |
| 旋转后仍非 4:3 的竖版、已是横版但比例不符、正方形 | 说明**仅旋转无法修正比例**，需裁剪或更换为符合 4:3 的横版文件 |
| 文件无法读取尺寸 | 提示确认文件可正常打开，或更换文件 |

处理完成后：「导出 / 查看失败清单」打开清单，「打开输出目录」查看成品；双击状态表某一行可直接打开该张成品。

## 2. 文档流程 → 程序实现的对应

| 文档步骤 | 程序实现 |
|---|---|
| 3.1–3.3 打开 XnConvert / 添加文件或文件夹 | 一次性批量导入；规则与路径一次设定，全程免逐张设置 |
| 3.4–3.5 动作 → 添加「文字」 | 内置时间水印渲染，无需逐张添加动作 |
| 3.6 读取 EXIF「拍摄日期」 | 严格读取 `DateTimeOriginal`；缺失即判失败并列入清单，要求补原图 |
| 3.7 格式「年/月/日 时:分:秒」、位置「右下」 | **系统固定** `%Y/%m/%d %H:%M:%S` + 右下（24/20 px 固定边距），不可修改 |
| 3.8 字体「微软雅黑」、尺寸 70、阴影「启用」 | **系统固定**微软雅黑 70 px、白色文字、黑色 70% 阴影（偏移 2 / 模糊 2），不可修改 |
| 3.9 输出文件夹 + 批量改名 | 指定输出目录；文件名改为按客户规范生成（见下） |
| 3.10 点击「转换」 | 一键「开始批量处理」 |
| 3.11 显示状态 | 逐张状态表（成功/警告/失败/跳过 + 失败阶段与原因）、进度、汇总、4 份报告 |

**命名口径变更**：V2 步骤 3.9 界面示例的 `{Filename}_结果` 仅作归档用；客户规范 V1 p.3 / V2 §11 要求
`<ECU name>_<serial number>_<sequential number>`（例 `PeCu_2718281828_0001`），v1.1.0 默认模板改为
`{ecu}_{serial}_{seq}`，`{seq}` 为 4 位序号。

**分辨率口径变更**：V1 p.3「est. 21 MP」在 V2 §8/§10 被列为评价检查项，故交付成品亦须满足。
默认改为**不缩放（保持原分辨率）**并强制校验主输出 ≥2100 万像素。

## 3. 界面配置：3 项必填 + 高级设置

界面只有两块：顶部**必填信息**（前置、集中、明确标识）与「高级设置」页签（默认可不动）。

### 3.1 必填信息（顶部固定面板）

| 字段 | 说明 |
|---|---|
| ★ ECU 名称 | 客户命名 `<ECU>_<serial>_<seq>` 的第一段；按实物铭牌/客户清单确认，程序不预填 |
| ★ 样品序列号 | 命名第二段；同上，程序不预填 |
| ★ 输出目录 | 成品与报告位置；默认程序目录 `输出照片/`，建议独立于源照片目录 |
| 起始序号 | 可选，默认 1，决定 `<四位序号>` 的起点 |

★ 项未填满时「② 开始批量处理」保持禁用；空值输入框以浅红底色标识，右侧显示「必填 2/3 已填写」。
必填值随上次配置自动带入，**同一台机器上重复批次无需重新输入**。

### 3.2 时间水印（系统固定，界面不提供任何选项）

| 项目 | 固定值 |
|---|---|
| 是否启用 | 始终启用（不可关闭） |
| 时间来源 | EXIF 拍摄日期（`DateTimeOriginal` 优先；读不到即判缺少 EXIF 并失败） |
| 内容 | 仅时间（模块常量 `{time}`），不附加文字、标识、序号或文件名 |
| 格式 | `yyyy/mm/dd hh:mm:ss`（`%Y/%m/%d %H:%M:%S`） |
| 位置 / 边距 | 右下 / 24 × 20 px |
| 字体 / 字号 / 颜色 | 微软雅黑 / 70 px / 白色 100% |
| 阴影 | 启用，偏移 2、模糊 2、黑色 70% |

上述 22 个字段在代码中是常量 `config.WATERMARK_FIXED`，四道闸口保证不可改写：
**界面不暴露**（界面字段集 = 配置字段 − 这 22 项）、**规则文件载入时忽略**、
**预置方案不含**、**引擎入口强制回写**；若出现非固定值，配置校验直接报错。

### 3.3 高级设置（第 2 个页签，一般无需修改）

| 分组 | 关键项 | 默认值 |
|---|---|---|
| 输出规格 | 缩放方式 | **不缩放（保持原尺寸）** |
| | 主输出像素下限 | **21 MP（≥2100 万像素），强制校验** |
| | 目标宽 / 高 | 5292 × 3969（4:3，约 21 MP）；仅自定义缩放/报告版副本时生效 |
| | 像素规格 DPI / 输出格式 / JPEG 质量 | 300 / 同原格式 / 92 |
| | 留白背景色 | `#FFFFFF`（仅「适应留白」时可见） |
| 输出与命名 | 文件名模板 | **`{ecu}_{serial}_{seq}`** |
| | 同名文件时 / 保留 EXIF 元数据 | **自动加序号另存（默认不覆盖）** / 启用 |
| | 报告插图副本 / 后缀 | 关闭 / `_报告版` |
| 输出校验 | 输出后回读校验 | 启用 |
| | 成品最小字节数 / 源图像素安全上限 | 256 / 3 亿 |

「保存设置… / 载入设置…」可把高级设置存成 JSON 复用；「恢复默认」只复位高级设置，
**必填信息与已导入照片保持不变**。程序退出与每次开始处理时自动保存上次配置。
预置方案仍保留在代码内（`config.PRESETS`），界面不再提供，以减少操作步骤。

## 4. 输出物

处理结束后，**输出目录**内出现：

| 文件 | 内容 |
|---|---|
| `<ECU>_<序列号>_<四位序号>.jpg / .png` | 主交付成品。保持原分辨率（实测 53.87 MP）、300 DPI、右下角时间水印、保留 EXIF/ICC |
| `<同名>_报告版.jpg`（可选） | 报告插图轻量副本，仅在开启时生成，明确标注不满足 2100 万像素 |
| `失败清单.csv` | UTF-8 BOM，Excel 双击直开。列出失败/跳过/警告照片、失败阶段、具体原因、建议处理、原路径 |
| `失败清单.txt` | 同上，纯文本便于粘贴到邮件/工单 |
| `处理报告_时间戳.txt` | 版本、流程依据、耗时、统计、校验记录（含像素数合规）、**完整规则配置快照**、逐张结果 |
| `处理报告_时间戳.json` | 同上，机器可读，便于归档回溯 |

**失败照片不会产生成品**：程序先写临时文件、校验通过后才原子替换到目标路径；任何阶段失败都会清理临时文件。批次审计反向核对失败照片的尝试输出路径，发现残留会明确列出。

## 5. 逐张状态与失败原因

| 状态 | 含义 |
|---|---|
| 成功 | 已完成尺寸/DPI 调整、水印、导出，且通过输出回读校验与像素数合规校验 |
| 警告 | 已产出成品，但存在需人工核对的偏差（如时间戳非 `DateTimeOriginal`、字号自动缩小、字体回退、未执行回读校验） |
| 失败 | 未产出成品，状态表给出失败阶段与具体原因 |
| 跳过 | 同名输出已存在且策略为「跳过」；该路径不是本次产出 |

| 阶段 | 典型原因 | 建议 |
|---|---|---|
| 导入 | 文件损坏/截断、格式不支持、文件不存在、像素超安全上限 | 从相机重新导出或补拍；BMP/TIF/WEBP 常无 EXIF |
| 时间源 | **缺少 EXIF 信息**（唯一原因；策略固定为失败，无其它时间来源可选） | 请提供保留完整 EXIF 的原始照片 |
| 尺寸调整 | 目标尺寸过大、内存不足 | 降低目标尺寸或改「不缩放」 |
| 水印渲染 | 画布过小（目标尺寸过小导致水印放不下）、系统字体异常 | 改回「不缩放」或增大目标尺寸 |
| 导出 | 目录不可写、磁盘满、文件名/路径过长、非法字符 | 检查权限与磁盘；缩短模板或输出路径 |
| 输出校验 | 成品无法解码、尺寸/DPI/格式/大小不符、**像素数低于 21 MP** | 改用「不缩放」保持原分辨率，或降低下限（需客户确认） |

## 6. 必须知晓的边界条件（发客户 / 贴报告前请复核）

1. **≥2100 万像素现在被强制校验**：主输出低于 21 MP 直接判失败、不出成品。默认不缩放，保持原分辨率。
   如需缩小，只能缩到仍 ≥21 MP 的尺寸（如 5292×3969）；「报告插图副本」不参与该校验，
   但**明确标注不可替代主交付原件**。
2. **时间基准严格为 EXIF 拍摄日期**。触发判断只读取照片 EXIF 中的
   `DateTimeOriginal` / `DateTimeDigitized` / `DateTime`；三者均不可用时视为缺少 EXIF 信息，
   弹出提示窗口、该张判失败并列入清单。判断不依赖文件名、文件时间、JPEG 其它数据段或任何照片来源信息。
   窗口文案统一为：「缺少 EXIF 信息。请提供保留完整 EXIF 的原始照片。」
3. **合规命名由程序生成，前缀由人填写**。ECU 名称与序列号是必填字段，程序不预填——铭牌目视值
   （`EEPH` / `T55B92BD20126B118X0000119461114`）与 V2 文档示例（`...B119X...`）不一致，
   任何 OCR 推断值都不得自动进入客户文件名。参考值见 `真实照片核查报告_20261107.md`（标注「未核实」）。
4. **拍摄顺序**（序列号标签闭环、六面视图、连接器、异常细节）**未做程序化校验**，需人工按 V1 p.3 / V2 §9 核对。
5. **输出回读校验不含**水印可见性、时间戳语义正确性、命名规范符合性、拍摄顺序、画质（对焦/反光）。
6. 「同原格式」实为 JPG→JPEG、PNG→PNG，TIF/BMP/WEBP→JPEG；HEIC/HEIF 不受支持。
7. 四种缩放取舍：`contain` 补边但可能放大；`cover` 会裁掉边缘（**可能裁掉缺陷细节，证据照片不建议**）；
   `stretch` 会变形；`none` 不缩放但批次内尺寸可能不一致（审计会提示）。
8. **水印外观是系统固定的**（微软雅黑 70 px、右下、白色 + 阴影），界面与规则文件都不能改。
   70 px 在 8768 px 宽图上相对偏小（文档 3.8 规定 70，程序按文档保留）；若客户要求更醒目，
   只能由开发方调整 `config.WATERMARK_FIXED` 并以新版本发布，**不能现场配置**。
9. **输出目录建议独立于源照片目录**。程序已保护本批次所有源照片不被覆盖，但同目录混放不利于区分原件与成品。
10. **比例 / 方向检查只在导入时提示，不改变处理链路**：被标记的照片仍会按规则处理并导出，程序不会自动旋转、裁剪或剔除。
    需由操作人员先按提示修好源文件再处理；输出回读校验也不含 4:3 比例。
    判定依据是文件内编码的像素宽高（不是照片在查看器里经 EXIF 方向校正后的显示尺寸）；
    带方向标记 6/8 的竖版文件在引擎中会自动校正为 4:3 横版，故提示同时说明「无需手工旋转」。
    当前 26 张真实照片为 8768×6144（约 1.43:1），全部会被列入「横版但比例不符 4:3」。
11. **时间水印不可编辑、不可选择格式、不可做任何自定义**：内容恒为 `yyyy/mm/dd hh:mm:ss`，
    不附加文字/标识/可变信息；同一张照片重复处理结果完全一致（时间只来自 EXIF，不随时间变化）。
    若客户要求其它格式或附加信息，属需求变更，须修改 `config.WATERMARK_FIXED` 并发布新版本。
12. **同名文件默认不覆盖**：`on_exists` 默认「自动加序号另存」（`_1`、`_2` …）。
    开始处理前会统计「目标文件名已存在」的数量并弹窗说明后果；只有操作人员显式改成「覆盖同名文件」
    才会提示不可恢复。注意：序号靠文件名后缀区分，**不代表业务序号**，交付前仍应按客户要求核对。

## 7. 版本管理与可回溯性

- 版本号唯一来源：`VERSION` + `src/__init__.py::__version__` = `1.2.1`；发布 tag `v1.2.1`
  （`v1.2.0`、`v1.1.2`、`v1.1.1`、`v1.1.0`、`v1.0.0` 为历史版本）。
- `CHANGELOG.md`：按语义化版本记录全部新增、修复、验证与已知边界。
- git 提交按模块增量提交，提交说明写明「改了什么 / 为什么 / 验证结果」。
- `dist/BUILD_INFO.txt`：构建时间、Python / PyInstaller 版本、**构建时 git HEAD 与提交说明**、
  `git_dirty`、exe 大小与 sha256、**每个源码文件的 sha256**。
- `build.py` 在工作区存在未提交源码改动时**拒绝产出可交付 exe**。
- exe 与 `BUILD_INFO.txt` 是可重建的构建产物，不入库；`build_exe.bat` 可在同一提交上重建。

### 开发 / 验证命令

```bat
py -3 main.py                          :: 或 run.bat / 双击 exe
py -3 tests\run_all.py                 :: 全量验证：核心 114 项 + GUI 16 个检查点
py -3 build_exe.bat                    :: 提交后重新打包 + 写 BUILD_INFO
py -3 tests\validate_frozen.py         :: 冻结 exe 验收（版本元断言 + 端到端 + 双击窗口实测）
```

`PhotoWatermark.exe --version <out.json>` 与 `--selftest <workdir>` 是无界面自检入口，结果写入 JSON 文件。

## 8. 常见问题

**Q：弹出「缺少 EXIF 信息」提示窗口是什么意思？**
说明部分照片的 EXIF 中读不到拍摄日期，无法生成时间水印。请提供保留完整 EXIF 的原始照片后重新导入。
这些照片不会被静默跳过：状态表会标记，处理后列入失败清单；含 EXIF 的照片不受影响，按原流程正常处理。

**Q：弹出「照片比例 / 方向检查」窗口，是不是照片没导入成功？**
不是。所有照片都已正常导入，弹窗只是提示，关闭后可继续处理其余合格照片；异常行在状态表标为「比例异常」。
目标要求是**符合 4:3 的横版照片**：竖版 3:4 的照片旋转 90° 即可满足（方向可靠时给出顺/逆时针建议，
否则请人工确认）；比例本身不符的照片仅旋转无法修正，需裁剪或更换文件。程序不会自动旋转或裁剪，
请按提示修好源文件后再处理。

**Q：能改水印格式、字号、位置或加公司标识吗？**
不能。时间水印由系统统一生成并固化：内容只有 `yyyy/mm/dd hh:mm:ss`，位置右下，微软雅黑 70 px。
界面没有任何水印选项，规则文件里的同类字段会被忽略，引擎入口还会再强制回写一次。
如客户要求变更，须修改常量并发布新版本。

**Q：每次都要重新填 ECU 名称和序列号吗？**
不需要。三项必填值随上次配置自动带入；换批次时只改变化的部分。未填满时「开始批量处理」保持禁用，
不会出现点开后才报错的情况。

**Q：为什么必须手填 ECU 名称与序列号？**
客户规范 `<ECU>_<serial>_<seq>` 中的两段是实物铭牌信息；不同批次、不同放大图与文档示例之间存在字符差异。
自动 OCR 会把误差写进客户交付文件名，因此设计为界面必填、程序不预填。

**Q：重复跑同一批照片会覆盖上一次的成品吗？**
不会。默认「自动加序号另存」，同名成品会变成 `..._1.jpg`、`..._2.jpg`。
开始处理前程序会统计目标文件名已存在多少个并弹窗告知；只有把「同名文件时」改成「覆盖同名文件」
才会真正覆盖，且会二次确认。同名统计用的是命名模板预测，模板含 `{time}` 时按 EXIF 拍摄时间预测。

**Q：可以直接用 2400×1800 贴报告吗？**
可以开启「另出报告插图副本」，程序会额外生成轻量版（文件名带报告版后缀），但主交付原件仍保持原分辨率。
报告副本不满足 2100 万像素，处理报告会明确标注，请勿用其替代交付原件。

**Q：换电脑后字体变了？**
程序使用系统字体（固定微软雅黑）。若目标机器无该字体，会回退并在状态中给出警告；
水印外观不可由操作人员指定，需要随程序分发字体时请联系维护人员。

**Q：程序打不开 / 闪退？**
优先使用 `dist/PhotoWatermark.exe`；源码运行需 Python 3.10+ 且 `tkinter` + `Pillow` 可用。`run.bat` 会自动检查依赖。
