# 批量照片时间水印处理程序 v1.0.0

面向操作人员的 Windows 桌面程序：一次批量导入照片，无需逐张设置，自动完成
**尺寸与像素规格调整 → EXIF 拍摄日期时间水印 → 批量导出 → 逐张状态与失败清单**。

- **免安装版**：`dist/PhotoWatermark.exe`（单文件，目标机器无需 Python）
- **源码运行**：双击 `run.bat`（需 Python 3.10+ 与 `Pillow`，执行 `pip install -r requirements.txt`）
- **流程依据**：`How to photo documentation_V2.doc`（V2.0，2026/05/25）第 9 节步骤 **3.1–3.11**

---

## 1. 三步完成一次批量处理

| 步骤 | 操作 | 说明 |
|---|---|---|
| ① 导入 | 「添加照片」或「添加文件夹」 | 可多选、可勾选「包含子文件夹」、自动去重。支持 JPG / PNG / BMP / TIF / WEBP |
| ② 确认规则 | 「规则配置」页，必要时调整；或选一套预置后点「应用预置」 | 默认即为文档预置，**通常无需修改**。输出目录默认在程序目录 `输出照片/`，可改 |
| ③ 执行 | 「开始批量处理」 | 后台处理，进度条 + 逐张状态实时刷新；完成后自动写出失败清单与处理报告 |

处理完成后：「导出 / 查看失败清单」打开清单，「打开输出目录」查看成品；
双击状态表某一行可直接打开该张成品。

## 2. 文档流程 → 程序实现的对应

| 文档步骤 | 程序实现 |
|---|---|
| 3.1–3.3 打开 XnConvert / 添加文件或文件夹 | 一次性批量导入；规则与路径一次设定，全程免逐张设置 |
| 3.4–3.5 动作 → 添加「文字」 | 内置时间水印渲染，无需逐张添加动作 |
| 3.6 读取 EXIF「拍摄日期」 | 优先 `DateTimeOriginal`；缺失时按「拍摄日期缺失时」策略处理 |
| 3.7 格式「年/月/日 时:分:秒」、位置「右下」 | 默认 `%Y/%m/%d %H:%M:%S` + 右下（X/Y 留白 24/20 px 安全边距） |
| 3.8 字体「微软雅黑」、尺寸 70、阴影「启用」 | 默认微软雅黑 70 px、白色文字、黑色 70% 阴影（偏移 2 / 模糊 2） |
| 3.9 输出文件夹 + 批量改名 `{Filename}_结果` | 默认输出目录 + 模板 `{name}_结果`，保留 EXIF/ICC 元数据 |
| 3.10 点击「转换」 | 一键「开始批量处理」 |
| 3.11 显示状态 | 逐张状态表（成功/警告/失败/跳过 + 失败阶段与原因）、进度、汇总、4 份报告 |

程序在文档 3.1–3.11 之外，按需求补充了「尺寸与像素规格调整」和「失败照片识别与校验」。

## 3. 规则配置（统一、可调整、可另存）

界面分 5 组，共 29 项；所有项均可在一次批量处理中统一生效，改完立即作用于整批照片。

| 分组 | 关键项 | 默认值 |
|---|---|---|
| ① 尺寸与像素规格 | 目标宽 / 高 | 2400 × 1800 px（4:3） |
| | 缩放方式 | 适应留白（不裁切、不变形） |
| | 像素规格 DPI | 300 |
| | 输出格式 / JPEG 质量 | 同原格式 / 92 |
| ② 时间水印 · 内容与时间 | 时间来源 | EXIF 拍摄日期（文档 3.6） |
| | 时间格式 | `%Y/%m/%d %H:%M:%S`（年/月/日 时:分:秒） |
| | 内容模板 | `{time}`（必须含 `{time}`；另支持 `{filename}` `{name}` `{seq}`） |
| | 拍摄日期缺失时 | 判定失败并列入失败清单（推荐） |
| ③ 位置 / 字体 / 阴影 | 位置 | 右下（9 宫格可选） |
| | 字体 / 字号 / 单位 | 微软雅黑 / 70 / px（可切 pt 按 DPI 换算） |
| | 颜色 / 不透明度 | 白色 / 100%（**不得为 0**，水印须可见） |
| | 阴影 | 启用，偏移 2、模糊 2、黑色 70% |
| ④ 输出与命名 | 输出目录 | 程序目录 `输出照片/` |
| | 文件名模板 | `{name}_结果`（文档 3.9 截图） |
| | 同名文件 / 起始序号 | 覆盖 / 1 |
| ⑤ 失败识别与校验 | 输出后回读校验 | 启用 |

预置方案：

| 名称 | 用途 |
|---|---|
| 文档预置 · 报告/客户交付（2400×1800 @300DPI） | **默认**。尺寸统一、文件适中，便于发客户与贴报告 |
| 高像素归档 · 保持原尺寸（不缩放，需自行核对像素数） | 不缩放，仅加水印与 DPI；用于原件归档 |
| 轻量预览 · 1600×1200 @150DPI | 小图快速预览 |

「保存规则… / 载入规则…」可把整套规则存成 JSON 归档复用；程序退出与每次开始处理时会自动保存上次配置。

## 4. 输出物

处理结束后，**输出目录**内出现：

| 文件 | 内容 |
|---|---|
| `<模板生成的名字>.jpg / .png` | 成品照片。尺寸/DPI 一致，右下角时间水印，保留 EXIF（及 ICC） |
| `失败清单.csv` | UTF-8 BOM，Excel 双击直开。列出失败/跳过/警告照片、失败阶段、具体原因、建议处理、原路径 |
| `失败清单.txt` | 同上，纯文本便于粘贴到邮件/工单 |
| `处理报告_时间戳.txt` | 版本、流程依据、耗时、统计、校验记录、**完整规则配置快照**、逐张结果 |
| `处理报告_时间戳.json` | 同上，机器可读，便于归档回溯 |

**失败照片不会产生成品**：程序先写临时文件、校验通过后才原子替换到目标路径；
任何阶段失败都会清理临时文件。批次审计会反向核对失败照片的尝试输出路径，
若发现残留会明确列出，不会无条件报「通过」。

## 5. 逐张状态与失败原因

| 状态 | 含义 |
|---|---|
| 成功 | 已完成尺寸/DPI 调整、水印、导出，且通过输出回读校验 |
| 警告 | 已产出成品，但存在需人工核对的偏差（如时间戳非 `DateTimeOriginal`、字号自动缩小、字体回退、未执行回读校验） |
| 失败 | 未产出成品，状态表给出失败阶段与具体原因 |
| 跳过 | 同名输出已存在且策略为「跳过」；该路径不是本次产出 |

失败阶段与常见原因：

| 阶段 | 典型原因 | 建议 |
|---|---|---|
| 导入 | 文件损坏/截断、格式不支持、文件不存在、像素超安全上限 | 从相机重新导出或补拍；BMP/TIF/WEBP 常无 EXIF，建议先转 JPG |
| 时间源 | 缺少 EXIF 拍摄日期；模板缺 `{time}`；时间格式非法 | 勿用微信/截图等剥离 EXIF 的传输方式；必要时改用「文件修改时间」（会标警告，需人工核对） |
| 尺寸调整 | 目标尺寸过大、内存不足 | 降低目标尺寸或改「不缩放」 |
| 水印渲染 | 字体文件缺失、字号过大、画布过小、字体不透明度为 0 | 检查字体与字号；水印须肉眼可见 |
| 导出 | 目录不可写、磁盘满、文件名/路径过长、非法字符 | 检查权限与磁盘；缩短模板或输出路径 |
| 输出校验 | 成品无法解码、尺寸/DPI/格式/大小不符 | 重试该张；检查磁盘写入稳定性 |

## 6. 必须知晓的边界条件（发客户 / 贴报告前请复核）

1. **「≥2100 万像素」是拍摄原件的评价要求，程序不校验、也不保证成品达到该指标。**
   默认输出 2400×1800 = 432 万像素，用于报告/客户交付；原始照片请另行归档。
   处理报告会写入该提示。「适应留白」会按需等比缩放，**可能放大低像素原图**，请人工判断清晰度。
2. **命名规范需由源文件名保证。** 文档 3.9 截图用 `{Filename}_结果`，而第 10/11 节要求
   `<ECU name>_<serial number>_<sequential number>`，两者存在冲突。默认遵循 3.9；
   把模板改成 `{name}` 只是不追加 `_结果` 后缀，**不会自动把不规范的文件名改成规范格式**。
3. **输出校验范围有限**：只校验可解码、目标尺寸、DPI、格式、文件大小；
   **不校验**水印可见性、时间戳是否正确、像素总数、命名规范。这些需要人工抽检。
   关闭「输出后回读校验」时，完成提示会明确写「未执行」。
4. **EXIF 是时间水印的唯一可靠来源。** 回退到 `DateTime`/`DateTimeDigitized`/文件修改时间/固定文本时，
   程序一律降级为「警告」并在报告中标注「非 EXIF 拍摄日期」，此类照片不建议直接作为交付证据。
5. **「同原格式」** 实为 JPG→JPEG、PNG→PNG，TIF/BMP/WEBP→JPEG。
6. **四种缩放的取舍**：`contain` 补边但可能放大；`cover` 铺满但会裁掉边缘（**可能裁掉缺陷细节，证据照片不建议**）；
   `stretch` 会变形；`none` 不缩放但批次内尺寸可能不一致（审计会提示）。
7. **输出目录建议独立于源照片目录。** 程序已保护本批次所有源照片不被覆盖，
   但同目录混放仍不利于区分原件与成品。
8. **字号 70 按输出图像素解释**（对应 XnConvert「尺寸 70 / 单位 点」）；
   界面可切换 `pt`，按 `pt × DPI / 72` 换算。
9. 输入 **HEIC/HEIF 不受支持**（Pillow 无内置解码器），请在相机端设为 JPEG 或先转换格式。

## 7. 版本管理与可回溯性

- 版本号唯一来源：`VERSION` + `src/__init__.py::__version__` = `1.0.0`；发布 tag `v1.0.0`。
- `CHANGELOG.md`：按语义化版本记录全部新增、修复、验证与已知边界。
- git 提交按模块增量提交，提交说明写明「改了什么 / 为什么 / 验证结果」。
- `dist/BUILD_INFO.txt`：构建时间、Python / PyInstaller 版本、**构建时 git HEAD 与提交说明**、
  `git_dirty`、exe 大小与 sha256、**每个源码文件的 sha256**。
- `build.py` 在工作区存在未提交源码改动时**拒绝产出可交付 exe**（需 `--allow-dirty` 才放行，
  且该产物不得交付）。
- exe 与 `BUILD_INFO.txt` 是可重建的构建产物，不入库；`build_exe.bat` 可在同一提交上重建，
  用 `tests/validate_frozen.py` 核对源码哈希与产物一致性。

### 开发 / 验证命令

```bat
py -3 run.bat                          :: 或直接 python main.py
py -3 tests\run_all.py                 :: 全量验证：核心 77 项 + GUI 9 项
py -3 build_exe.bat                    :: 提交后重新打包 + 写 BUILD_INFO
py -3 tests\validate_frozen.py         :: 冻结 exe 验收（版本元断言 + 端到端 + 双击窗口实测）
```

`PhotoWatermark.exe --version <out.json>` 与 `--selftest <workdir>` 是无界面自检入口，
结果写入 JSON 文件（窗口程序无控制台，不依赖 stdout）。

## 8. 常见问题

**Q：一批照片全部提示「缺少 EXIF 拍摄日期」？**
原图大概率经过微信、截图或某些编辑软件，EXIF 已被剥离。请用原相机文件；
确无 EXIF 时把「拍摄日期缺失时」改为「回退到文件修改时间」，但成品会标警告，需人工核对时间。

**Q：水印时间不对？**
查看失败清单/详情里的「拍摄时间」与告警；若显示「非 EXIF 拍摄日期」，说明用了回退字段。
另外 EXIF 时间无时区信息，程序按相机记录的本地时间原样呈现。

**Q：换电脑后字体变了？**
程序使用系统字体（默认微软雅黑）。若目标机器无该字体，会回退到本机可用字体并在状态中给出警告；
也可在「自定义字体文件」指定随程序分发的 `.ttf/.ttc`。

**Q：程序打不开 / 闪退？**
优先使用 `dist/PhotoWatermark.exe`；源码运行需 Python 3.10+ 且 `tkinter` + `Pillow` 可用。
`run.bat` 会自动检查依赖并给出提示。
